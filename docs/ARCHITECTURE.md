# Code map

Read the row for the feature you are changing. [AGENTS.md](../AGENTS.md) contains working rules; [PRODUCT.md](PRODUCT.md) contains current product boundaries. Paths below are relative to the repository root.

## Find a task or file

```sh
npm run --silent map                              # list task areas
npm run --silent map -- progress                  # owners and focused checks
npm run --silent map -- subject-progress-store.js # exports, imports and direct importers
```

The command reads this table and current source, without an index or cache. Unique JavaScript filenames work directly; ambiguous names list exact paths. File results include exports, imports and direct test importers with line numbers (`L` refers to the selected file). It scans only `src/`, `scripts/`, `tests/` and the two server entrypoints. Literal JavaScript imports/re-exports (including lazy imports) are indexed; CSS/HTML references, computed imports and runtime URLs still need a targeted search before moving or deleting files. No arguments or `--help` show usage. `--silent` removes npm's command banner, not errors or results.

`npm run check` validates every owner path and focused command in this table. Update the existing row when moving its files or changing a check. This is a task map, not an exhaustive file inventory.

## State and boundaries

`main.js` creates one learner session and one subject progress store, shared by Home and the lesson journey. UI calls those services; it does not create parallel stores or directly access account endpoints. Domain modules implement pure rules shared by browser and server.

Progress adapters: `session-progress.js` for guests, `indexeddb-progress.js` for fixture members, `server-progress.js` for HTTP members and their account-bound IndexedDB outbox. Local reads and writes are serialized per owner; a save succeeds after the local transaction commits. HTTP sync runs separately, retains unacknowledged operations and retries on reconnect, focus, visibility, page restoration and every 30 seconds while visible. Network failures and recovered legacy records stay quiet; actual local-storage failures retain retry feedback. The server confirms rewards; its daily celebration can arrive through `SaveResult.whenSynced` without blocking lesson completion. Completion/XP are monotonic; mutable review answers follow committed order. Answers persist their local activity day and award the question’s allocated XP only on first correctness. Each adapter claims the day's streak celebration across all owner records within its write transaction. Home uses the 100-level scale in `progression.js`; `subject-completion.js` overlays a full-screen daily celebration without replacing the question. `daily-streak.js` sequences a paused fade, a quick stretched Rocky peek with left/right glances, a fast rise and readable greeting, a move to the top, then the larger centered flame, counter and checkmark burst. Continue dismisses it; it never closes automatically. Reduced motion shows the final state; dismissal and navigation remove the overlay and its timers. Preserve legacy import keys and retry behavior. Retired developer routes normalize to Home.

Each navigation owns a `view-lifecycle.js` operation with `signal`, `isCurrent()` and `add(cleanup)`. New navigation aborts the old operation. Check the captured operation before committing asynchronous results; cleanup runs once. `media-ready.js` scopes image decoding/retry to the affected surface, and `view-motion.js` handles motion/reduced motion. Do not hide the whole page to mask loading.

The first-account Rocky tour stores its own account-scoped stage, independently of lesson progress, preserving older completed markers. Account creation opens the first ICT MCQ directly, followed by a flashcard; progress explanations follow completion. Its spotlight uses rounded SVG cutouts around live, visible controls and reserves space beside the current explanation, moving between the question, footer actions and report flag. `rocky-coach.js` animates the cropped production drawing in `rocky-coach.svg` with finite speaking/encouraging gestures and an attentive rest pose; reduced motion changes position instantly without character or travel animation. Skipping or signing out removes listeners, masks, reserved space and carried mascot. Only the tour passes `demoMode` to the lesson renderer. `lesson-demo.js` selects the first ICT MCQ (or an easy MCQ for other subjects) and a flashcard without mutating the published bank, maps demonstration answers back to canonical question IDs, and never claims a previewed MCQ was solved. Normal lesson entry restores the original sequence. Ratings, reports and personal question hiding use `/api/question-feedback`, authenticated owner headers, validated published identities and account-bound database tables; fixture mode uses a separate local feedback cache. Confirmed hiding survives navigation and is awaited before loading lessons or reviews. Hidden preferences use the shared canonical question identity (including mathematics aliases and duplicate placements); the lesson renderer, review list and question-filter catalog exclude them without mutating content, answers, progress or rewards.

Home reads question IDs from the small generated `ict/question-index.js`; banks and parsing load only with lessons. Regenerate it with `node scripts/update-ict-question-index.mjs` after curriculum changes. Published ICT content loads through `subject-lesson-registry.js`; `ict/exam-lessons.js` filters the student course to questions only. Five lesson circles aggregate question progress over preserved part records; `subject-question-progress.js` owns that calculation. Historical progress identities remain valid; the unused day catalog and developer lesson tools have been removed. `TOTAL_DAYS = 112` preserves legacy rank helpers; it is not the ICT catalog size. Retired full-stack lessons and unused map artwork live in Git history.

Mathematics uses the same Markdown question pipeline and progress owners. `mathematics/math-course.js` lists the 25 indexed lessons and their stable question IDs; `mathematics/source-coverage.json` tracks catalog counts, recovered-source mappings, source issues and remaining coverage gaps. Original prompt/answer crops and provenance live in `assets/lessons/mathematics/source-crops/`. Each mathematics module contains only its indexed questions; historical subject aliases load the same canonical lesson object. Mathematics lesson text uses Amiri with a math-font fallback for stretching operators. Symbol rendering samples are test fixtures, outside the learner catalog.

Question explanations have one runtime owner: the corrected 2026-10-24 Markdown in MCQ explanations and flashcard solutions, shared by HTTP and fixture mode. The canonical bank contains 7,229 questions after exact source repeats were consolidated. Retired question IDs resolve through part metadata, preserving saved progress, rewards and purchased explanations. Source confirmations live with the curriculum-evidence asset provenance; the supplied ZIP retains the original review archive. Older mathematics and Islamic URLs resolve through compatibility lookups without duplicate registry entries. The shared question footer offers a permanent 50-gem unlock, included with Super. The progress API validates the published question and available content before atomically debiting gems and recording its canonical account-bound entitlement. Retries and mathematics aliases share the unlock; unavailable explanations never charge. A full-screen section slides up with Amiri text and spaced equations; closing or navigation cancels its work without answering the question or changing progress.

Chemistry uses the same Markdown question pipeline and progress owners. `chemistry/chemistry-course.js` contains navigation metadata for three units and 21 lessons; registered lesson modules load the replacement collection's 912 questions lazily (384 MCQs and 528 written flashcards). `chemistry/source-coverage.json` retains the supplied page ledger, answer evidence, 48 duplicate occurrences, 16 blocked source items and archive hash. `assets/lessons/chemistry/source-crops/sources.json` records the 76 referenced original crops; five crops used only by blocked questions remain in the separate source ZIP.

Biology follows the Ministry's Gaza packet: three units, nine chapters and 30 topic parts. `biology/biology-course.js` contains navigation metadata; chapter modules load the new collection's 1,227 ready questions lazily. Mixed genetics remains review practice within the non-Mendelian chapter. `biology/source-coverage.json` retains the supplied page/item audit, exclusions, unresolved items and the verified Ministry book hash; `assets/lessons/biology/source-crops/sources.json` records the 100 referenced original crops. Hero and path artwork use compact WebP without duplicate PNG fallbacks; original images and PDFs are archived separately. Rocky SVG drawings and animation values remain exact. ## Extension recipes

- **Add a subject/lesson:** add catalog metadata, then content under `src/data/lessons/<subject>/`; register it and add roadmap boundaries. Use [LESSON_AUTHORING.md](LESSON_AUTHORING.md). Reuse the parser/renderers and preserve published IDs; do not create a subject-specific service or duplicate a shell.
- **Change persistence:** start in the shared progress store and pure domain rules; update its actual IO adapter. Test interruption, retries, learner isolation and concurrent writes. No storage migration for cosmetic renames.
- **Add tooling:** operations stay in `scripts/`; browser journeys/helpers in `tests/browser/`; Node tests stay `tests/*.test.mjs`. Keep the dependency-free server and current static packaging unless a concrete requirement justifies more.

## Gates

`npm run check` runs syntax, selective checked JavaScript, Node tests, reference/import validation and size budgets. Browser-to-server imports and domain-to-UI/storage coupling fail validation. `verify` adds the full Chromium/accessibility, UI, progress, render, explanation formatting, assets and splash checks. `release` adds packaging, the API-free fixture journey, Firefox/WebKit, the admin browser journey and the Cloudflare runtime/streaming checks. All full gates reject scope-shortening flags.

Browser tests start isolated servers and disposable data. `CHROME_BIN` overrides discovery; `BROWSER_SCREENSHOT_DIR` optionally retains images. Focused flags are for investigation only. The accessibility suite reports the preserved palette's known contrast exceptions; other WCAG violations block the gate. A passing functional gate does not imply full accessibility or product release readiness.
