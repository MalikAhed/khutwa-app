# Code map

Read the row for the feature you are changing. [AGENTS.md](../AGENTS.md) contains working rules; [PRODUCT.md](PRODUCT.md) contains current product boundaries. Paths below are relative to the repository root.

## Find a task or file

```sh
npm run --silent map                              # list task areas
npm run --silent map -- progress                  # owners and focused checks
npm run --silent map -- subject-progress-store.js # exports, imports and direct importers
```

The command reads this table and current source, without an index or cache. Unique JavaScript filenames work directly; ambiguous names list exact paths. File results include exports, imports and direct test importers with line numbers (`L` refers to the selected file). It scans only `src/`, `scripts/`, `tests/` and the two server entrypoints. Literal JavaScript imports/re-exports (including lazy imports) are indexed; CSS/HTML references, computed imports and runtime URLs still need a targeted search before moving or deleting files. No arguments or `--help` show usage. `--silent` removes npm's command banner, not errors or results.

`npm run build` validates the owner paths and focused commands in this table. The checks listed are choices: run only the ones relevant to the change. Update the existing row when moving its files or changing a check. This is a task map, not an exhaustive file inventory.

## Runtime boundaries

`main.js` creates one learner session and one subject progress store. UI calls these shared services; domain modules contain pure rules. Keep storage keys and published subject/lesson/part/question IDs stable. Historical aliases and retired IDs still resolve to the canonical questions so updates preserve progress and paid unlocks.

HTTP progress uses `server-progress.js` with an account-bound IndexedDB cache/outbox. Guest and fixture progress use separate adapters. Local transactions complete before acknowledging saves; unacknowledged HTTP operations retry on reconnect and focus. Never clear progress to refresh content. Each view owns its cancellation and cleanup through `app/view-lifecycle.js`; stale work must not attach to a different view or account.

`background-loading.js` and one cancellable download queue prioritize the selected lesson and pause optional work during input/navigation. `main.js` configures the loader with the current account type and subscribes it to account changes. Free accounts fetch the active lesson and, on a suitable connection, at most the next lesson’s first stage; they do not install the entire app or see the offline-installation card. Paid accounts install every catalogued lesson, explanation and image once, resume partial downloads, and reuse unchanged verified files across releases. 100% and the new offline HTML shell require all files to be saved. Previously saved content is never removed on downgrade. Free startup verifies only the selected lesson scope, avoiding a full-cache read after a paid account switches to free; additional saved files are verified lazily before reuse. Islamic authored banks load lazily from the existing registry rather than entering the initial helper graph. The content worker never caches API responses or the Students page. Exact SHA-256 checks protect file reuse, and the last complete offline shell remains available through interrupted updates. Four Super background/foreground assets use compressed WebP with preserved alpha.

Browser offline identity is owned by `services/offline-access.js`: seven days from a successful server-dated account check, with a sticky clock-rollback gate and no progress deletion. `ui/offline-access.js` blocks free study during outages and paid study after the seven-day lease expires, until a real account check succeeds; downloaded lessons and the existing IndexedDB outbox survive browser restarts. `services/preview-updates.js` checks deployed releases on startup/reconnect/focus and every visible minute, stages hash-verified runtime code without changing the current tab, and activates only outside lessons/forms/dialogs after outbox synchronization and fresh network confirmation. `tests/browser/browser-auto-updates.mjs` covers interruption and retry behavior. Rated-question counts update in place without restarting entrance animations. The app declares `only light` in its HTML/CSS. Bootstrap tracks touch versus keyboard input so tap focus does not draw keyboard rings. The loading state hides unready lesson controls. Result-banner surfaces extend behind rating controls, with 8 px above the rating card and 4 px before the slider; scroll cues retain straight corners.

The browser runtime is built from this repository. Cloudflare Pages forwards `/api/*` unchanged through the existing `BACKEND` binding and uses that backend to authorize `/students` before returning the packaged dashboard layout. Production is `khutwa-app`; staging is `khutwa-app-staging`. Those Workers use D1 and Durable Objects. `src/server/cloudflare-development.mjs` proxies the default local preview to that real backend, with offline profile fallback. The other `src/server/` modules provide the isolated Node/SQLite test backend, **not** the source deployed to the Worker. See [OPERATIONS.md](OPERATIONS.md) before changing server behavior; frontend deployment must not replace the live account backend.

The account-policy backend adds `server/cloudflare-browser-registration.mjs` and `server/cloudflare-daily-resources.mjs` as extensions of a recovered current Worker. `scripts/prepare-account-policy-worker.mjs` prepares that integration without publishing. Browser registration and shared quotas live in `server/browser-registration.mjs`, `server/browser-policy-store.mjs` and `server/browser-allowance.mjs`; account progress remains in `server/progress-store.mjs`; midnight calculation and retired trial eligibility live in `domain/learner-resources.js`. Free answers use the existing durable outbox and wait for server acknowledgement; paid answers retain offline saving. Follow the recovery and publication instructions in [OPERATIONS.md](OPERATIONS.md#account-policy-backend).

`domain/free-practice.js` owns unlimited attempts in the first two visible published lessons of each subject and Super-only selection of unsolved slider questions. Free accounts have seven daily hearts for later lessons, with both account and browser limits enforced server-side. Previously solved questions remain freely selectable using the current learner’s saved solve history. Slider scrolling and normal Continue stay free; blocked selections keep the current question and open the Super invitation. The old daily skip allowance/cursors remain inactive and preserved through `QUESTION_NAVIGATION_LIMIT_ENABLED=false`. `browser_registrations` prevents extra browser signups, while `browser_heart_attempts` reserves debits across account Durable Objects and keeps retries idempotent. The shared progress store owns seven-gem first-correct-solve rewards in `answer_gem_rewards`; account balances/progress remain separate. `services/learner-resources.js` receives confirmed balances and checks free answers online. `ui/heart-depletion.js` owns the Super invitation using `domain/super-plans.js`; paid offline access retains seven-day server verification. Focused checks include `tests/browser-policy.test.mjs`, `tests/browser/browser-free-access.mjs` and the isolated Cloudflare policy/security runtime fixtures.

`ui/super-subject-picker.js` owns the selected-subject subscription step and WhatsApp message. It reuses the onboarding choice cards in a square grid with three columns on desktop and two on mobile, keeps a live subject count and per-subject annual total above the fixed golden action, and uses alpha-transparent generated icons from `assets/subjects/super-icons/`. The all-subjects plan retains its direct WhatsApp link. `node tests/browser/browser-super-presentation.mjs` covers the picker, pricing, keyboard selection, preserved choices, fixed footer, and both WhatsApp handoffs.

## Adding features

- Extend the existing owner from the table. Keep browser IO in `services/`, rendering in `ui/`, pure rules in `domain/`, curriculum in `data/`, local HTTP adapters in `server/`.
- Add lessons through the shared registry and roadmap. Follow [LESSON_AUTHORING.md](LESSON_AUTHORING.md); keep subject-specific source evidence in its coverage files. Run `node scripts/update-ict-question-index.mjs` when changing indexed ICT questions.
- Use `base.css` for shared tokens, feature stylesheets for internals, and `ui/media-ready.js` / `ui/view-motion.js` for media and motion. Preserve RTL, focus, reduced motion and the approved Rocky artwork.
- Temporary hidden features keep their existing data and URLs; use one flag. More remains unfinished. Do not add a framework or new persistence system without a concrete feature requirement.

## Checks

`npm run check` checks changed JavaScript syntax and the existing type-checked modules. Run the relevant behavior test or local browser journey for the feature. Documentation-only changes need link/command review, not an app build.

`npm run release` parses all JS, checks types and deployment behavior, then builds `_site/`; it does not deploy. Approval authorizes committing and pushing; pushes alone never publish. `npm run deploy` pushes and explicitly dispatches the approved commit to the Cloudflare workflow. Production checks cover HTTP account mode, the account API, protected Students routing, the release version and required browser libraries.

Full Node, browser, accessibility, compatibility and content audits remain available through `check:full`, `verify:full` and `release:full`. Use them for broad changes or a specific unresolved concern, not routine releases. See [AGENTS.md](../AGENTS.md) for the default workflow.
